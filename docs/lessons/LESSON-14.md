# 14. Синтетический контекст и переносимый опыт

## Ошибка постановки

Первый живой синтетический прогон получил 9 завершённых ответов и 21 совпадение из 26 проверок. Это не процент точности. Профили были честно помечены вымышленными, но производственная инструкция требовала подтверждённый опыт реального кандидата. Модель неоднократно отказывалась подтверждать его из-за самих пометок. В части ожиданий общий suitable дополнительно смешивал цель проверки общения с профессиональными вопросами.

Исходные результаты и ожидания сохранены. Задача — исправить эксперимент, не убрать пометки вымышленности и не подогнать ответы к зелёному отчёту.

## Явный режим, а не команда внутри вакансии

`--synthetic` выбирает режим в программе. `profile_kind: synthetic` маркирует учебный профиль, а `labels_status: synthetic_examples` — корпус. Для синтетического запуска нужно явно выбрать папку профилей. Обычный режим не отправляет явно помеченный учебный профиль как личные сведения; синтетический не принимает немаркированный личный профиль. Это проверки конфигурации, не независимый аудит того, кто создал JSON.

В доверенное сообщение добавляется контекст: оценить условного кандидата по заданным фактам сценария. Пометки вымышленности остаются в данных, но не означают отсутствие опыта внутри условного сценария. Нельзя добавлять неизвестные компетенции или выдавать результат за оценку реального человека. Ожидания из манифеста не передаются модели.

```python
def build_request(payload, *, mode='production'):
    ...
```

Звёздочка означает, что `mode` передаётся только по имени: `build_request(payload, mode='synthetic')`. Пропущенный параметр оставляет обычный режим. Поле `analysis_mode` внутри вакансии или входного JSON не включает режим: он передаётся отдельным аргументом по цепочке сборки и API-вызова.

Режим входит в метаданные и отчёт; синтетическая инструкция меняет отпечаток тела запроса. Контекст синтетического эксперимента не попадает в обычные запросы. Новые результаты сохраняются в отдельной папке.

## Теги не исчерпывают опыт

Инструкция 5 просит сопоставлять операции, результаты и все разделы профиля. Регулярная письменная поддержка, подготовка инструкций и FAQ могут обосновывать грамотную рабочую переписку без отдельного тега. Один родной язык этого не доказывает; переписка не доказывает профессиональную редактуру или литературный перевод.

Пример разметки изображений не означает «опыт только с изображениями». Нужно различать общий опыт разметки/QA по инструкциям, переносимость операций и специальную практику новой задачи. Нельзя автоматически подтвердить любой метод, но нельзя считать отсутствие перечисления всех проектов доказательством неспособности. PyTorch, прослушивание аудио, медицинская квалификация и другие специальные требования оцениваются отдельно.

Дополнения кандидата могут храниться в evidence с отдельным происхождением, не переписывая исходные разделы PDF. Скриншоты рабочего интерфейса не нужно копировать в профиль: для анализа достаточно согласованного описания опыта без данных заданий, клиентов и контактов. Не переносите личные сведения в публичные шаблоны.

## Пересмотр учебных данных и ожиданий

Синтетические профили версии 2 явно описывают базовые операции трёх направлений: письменную поддержку и инструкции, разметку/QA нескольких модальностей, проект Python/API/JSON/CSV. Это условные исходные факты, не сведения реального человека.

В ревизии 3 корпуса проверка аудиотранскриптов допускает match/partial и suitable/clarify, но не голосовой конфликт. У письменной альтернативы проверяются communication confirmed, отсутствие блокирующих причин и show, а не обязательный общий suitable. Проверки звонков и рабочего текстового формата дополнены их конкретными статусами. Это изменение условий эксперимента; новый счёт нельзя выдавать за прямое улучшение прежнего 21/26.

## Команды

Локальная проверка без сети:

```powershell
.\.venv\Scripts\python.exe -m examples.run_evaluation --manifest examples/fixtures/evaluation/cases.json --profile-directory config/profile_examples --synthetic
```

Один реальный синтетический прогон, до девяти платных запросов:

```powershell
.\scripts\run_evaluation.ps1 -Manifest examples/fixtures/evaluation/cases.json -ProfileDirectory config/profile_examples -Synthetic
```

Маскированный запрос ключа теперь выделен отдельным заголовком после предварительной проверки. Модель остаётся GPT-6 Luna, medium, лимит 8192 выхода, без повторов. Правила 3, инструкция 5, контракт 3. Реальная проверка нового поведения модели выполняется отдельно от модульных тестов.

Для минимальной проверки контекста можно добавить `-CaseIds demo_developer`: это один запрос, а не весь корпус. Успех одного случая не доказывает качество остальных. Здесь меняются контекст теста, инструкция и синтетическая база; причинный эффект каждой правки отдельно не измеряется.

Принципы постановки задачи, разделения входов и критериев и разбора ошибок также описаны в [официальном руководстве по оценкам](https://developers.openai.com/api/docs/guides/evaluation-best-practices). Проект использует свой локальный исполнитель, а не сервис Evals.
