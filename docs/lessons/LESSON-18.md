# 18. Полные карточки и история SQLite

Поиск даёт кандидатов, но для анализа нужны полные описания. `HHClient.detail(id)` получает карточку через `GET /vacancies/{id}` и проверяет, что ID ответа совпадает с запрошенным. Секрет передаётся в заголовке, не в URL.

## Почему SQLite

Библиотека `sqlite3` входит в Python. Отдельный сервер базы не нужен: история живёт в локальном `data/watcher.sqlite3`, исключённом из Git. Для нашего персонального сервиса этого достаточно.

В `history.py` две таблицы: `vacancies` хранит постоянный ID, `versions` — исходный JSON и отпечаток содержимого. Связь `REFERENCES` не позволяет версии ссылаться на несуществующую вакансию. `UNIQUE(vacancy_id, digest)` предотвращает повторное сохранение той же версии.

Отпечаток SHA-256 считается по выбранным содержательным полям, включая описание и условия. Счётчики просмотров не создают новую версию. Изменения зарплаты или графика сохраняются как факты, но не становятся критериями соответствия. Это история выбранных полей, а не универсальный детектор любого изменения ответа API.

`?` в SQL — место для параметра: SQLite подставляет значение отдельно от текста команды. Пользовательские строки нельзя собирать в SQL через f-строки.

`with self.db:` выполняет транзакцию: изменения одной карточки сохраняются вместе либо откатываются при ошибке. Соединение отдельно закрывает `History.__exit__`. Каждый успешно обработанный ID сохраняется сразу: ошибка следующего запроса не уничтожает предыдущие результаты.

## Запуск

Подставь путь к `candidates.json` нужного поискового запуска:

```powershell
.\.venv\Scripts\python.exe -m examples.fetch_hh_details --input "data/hh_api/<каталог запуска>/candidates.json" --limit 20
```

Это только план. Для загрузки добавь `--live`. Сценарий запросит HH-User-Agent и существующий токен со звёздочками. Первый токен заново не выдаётся. LLM не вызывается.

По умолчанию скачиваются только ещё не сохранённые ID. Повторный запуск продолжает со следующих новых карточек. `--refresh` разрешает повторное скачивание для проверки изменений: `new` — первая версия, `changed` — новое содержимое, `unchanged` — прежнее содержимое. Пока нет автоматического расписания перепроверки.

Лимит по умолчанию 20, максимум 200; между запросами пауза 0,6 секунды. При ошибке запрос не повторяется, цикл останавливается. Если поиск устарел и вакансия исчезла, такой ответ также остановит текущий запуск; обработку исчезнувших карточек добавим отдельно.

Сохранение не означает просмотр человеком: состояние «просмотрено» пока не реализовано. Профильные оценки также будут отдельными записями, чтобы одна карточка могла оцениваться по нескольким резюме. На этом шаге нет фильтрации кандидатов: не называем скачанные карточки рекомендациями.

Тесты проверяют сохранение после закрытия и открытия базы, неизменность первоначального JSON, отсутствие дублей от счётчика и создание новой версии при изменении описания. HTTP-проверки используют MockTransport, без сети.
