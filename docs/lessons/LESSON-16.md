# 16. Точная цитата и восстанавливаемая ошибка оформления

В реальном прогоне два ответа остановили обработку из-за завершающего знака цитаты: точка вместо точки с запятой или наоборот. API завершил ответы, но локальный валидатор требовал дословное совпадение. Повторять платный запрос для исправления одного знака не требуется.

## Граница восстановления

`repair_terminal_punctuation` возвращает копию ответа и список замен. Допустим один кандидат: тот же текст цитаты с заменой последнего `.` на `;` или наоборот. Кандидат должен дословно присутствовать в названии или описании. Если исходная цитата уже присутствует, она не меняется.

Слова, числа, отрицания, пробелы, регистр, е/ё и внутренние знаки этим способом не меняются. Нет нечёткого поиска или исправления по похожести. Не найден кандидат — остаётся ошибка.

```python
candidate = quote[:-1] + (';' if quote[-1] == '.' else '.')
```

Срез `quote[:-1]` берёт строку без последнего символа. Условное выражение выбирает только другой завершающий знак. Затем проверяется точное вхождение кандидата в исходный текст.

## Строгая проверка остаётся

API-адаптер сначала проверяет оригинальный ответ. Только при ошибке пробует узкое восстановление и заново запускает **всю** валидацию. Другой неверный ID, чужое основание, отсутствующее поле или несуществующая цитата по-прежнему отклоняют ответ.

Используется `copy.deepcopy`: изменение вложенной цитаты в копии не меняет оригинальный JSON-объект. В файле результата сохраняются:

- `output_text` — оригинальный текст модели;
- `assessment.analysis` — проверенная версия, в которой может быть локальная пунктуационная правка;
- `validation_recovery` — стратегия и список путей, значений before/after.

Отчёт отмечает число локально восстановленных цитат. Технический completed после восстановления не означает, что модель вернула идеальную исходную цитату. Проверка текста по-прежнему доказывает только наличие фразы, а не верность её смысловой трактовки.

## Исторические результаты

Уже сохранённые неуспешные записи не переписываются. Для них локально создаются отдельные артефакты восстановления с хешами оригинала и входа, списком замен и пересчитанной оценкой. Такой артефакт нельзя выдавать за исходный ответ модели или новый API-запуск. Старый отчёт об остановке остаётся исторически верным.

После остановки запускаются только ещё не выполненные случаи через `-CaseIds`. Ответ с ошибкой цитаты мог быть полностью обработан и учтён провайдером; автоматический повтор не нужен. При настоящем таймауте обработанность запроса может быть неизвестна — это отдельная ситуация.

## Проверки

Тесты покрывают копирование без изменения оригинала, точную замену конечного знака, сохранение уже точной цитаты, отказ при замене слов/отрицания/чисел/внутренней пунктуации/е-ё, сохранение исходного API-ответа и отказ при другой ошибке валидации. Сетевые обращения заменены mock-транспортом.

Модель, инструкция 5, правила 3 и контракт 3 не менялись: исправлен локальный обработчик результата. Производственные тексты и результаты остаются вне публичного репозитория.
