# 28. Единый итог партии

`report_saved` собирает результаты по исходным входам и ответам партии. Продолжение добавляет ответы в ту же папку, поэтому отдельно склеивать Markdown-файлы не нужно. Для первоначально неуспешного ответа используется отдельная локальная перепроверка, если она существует; происхождение видно в итоговом JSON.

Отчёт разделяет карточки для рассмотрения, профессиональный разбор и исключения по условиям. `clarify/show` означает возможность рассмотреть, а не гарантированное соответствие. `unsuitable/review` сохраняет профессионально неподходящую карточку в истории. Незавершённые входы и ошибки без перепроверки перечисляются отдельно, чтобы отсутствие результата не выглядело отказом.

Для Markdown используется `report.md`, для следующей интеграции — `summary.json`. В JSON находятся ID вакансии и профиля, группа, решение, маршрут, имя файла полного пересчёта и происхождение оценки. Несколько партий можно передать повторяемым `--batch`. Повторы пары ID–профиль устраняются; при нескольких версиях из разных партий пока используется первая встретившаяся, поэтому партии следует выбирать явно.

Сборка отчёта не отправляет запросов HH или Luna. Публикуются только код и урок; личный отчёт остаётся внутри игнорируемой папки `data`.
