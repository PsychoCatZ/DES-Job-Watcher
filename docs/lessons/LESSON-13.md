# 13. Противоположные случаи и явный выбор профилей

Сохраняем модель и настройки: GPT-6 Luna, medium, лимит 8192 выходных токена. Правила 3, инструкция 4, контракт 3. В этом шаге новые платные вызовы не выполнялись.

## Зачем расширять набор

Если все примеры хотя бы отчасти релевантны, отсутствие исключений мало говорит о качестве. Нужны разные причины результатов: прямое совпадение, другая основная профессия, явное обязательное видео, офис, письменная альтернатива, неизвестный канал. Упоминание AI само по себе не определяет соответствие.

Открытый корпус расширен с трёх до девяти вымышленных случаев. Это известный development-набор, не независимый holdout и не измерение качества подбора по реальному резюме.

| Случай | Что проверяем |
| --- | --- |
| demo_chat | Текстовая поддержка; отсутствие описания найма не мешает показу |
| demo_voice | Явные обязательные голосовые звонки без альтернативы |
| demo_data | Разметка при неизвестном канале общения |
| demo_developer | Python/API/JSON и явно разрешённая разработка с агентами |
| demo_other_profession | Финансовая работа с Claude остаётся другой профессией |
| demo_video | Явные обязательные видеовстречи без письменной альтернативы |
| demo_office | Обязательный офис при подходящих задачах и письменной работе |
| demo_audio_data | Готовые текстовые расшифровки как данные, без прослушивания |
| demo_text_alternative | Полноценная письменная замена видеовстреч, найма и обучения |

Основная работа другого типа даёт review, доступный пользователю; это не автоматическая сильная рекомендация. Явное критичное противоречие даёт exclude из обычной ленты с причиной. Наличие слова «аудио» не доказывает обязанность слушать или говорить.

## Две независимые оси выбора

Манифест выбирает вакансии, папка профилей выбирает сведения о кандидате. Можно взять синтетическую вакансию и реальное резюме, но это будет другой эксперимент, чем сравнение с учебными ожиданиями. Поэтому для воспроизводимого открытого прогона явно выбираем обе стороны:

```powershell
.\.venv\Scripts\python.exe -m examples.run_evaluation --manifest examples/fixtures/evaluation/cases.json --profile-directory config/profile_examples
```

Это проверка сборки без сети и ключа. Личные профили не читаются и не заменяются. Начальная команда настройки demo-профилей для этого запуска не требуется. Обычный запуск без этих параметров по-прежнему использует локальный личный корпус и профили.

## Как параметр проходит по Python

```text
--profile-directory
        ↓
prepare_cases(..., profile_dir=...)
        ↓
build_input(..., profile_dir=...)
        ↓
load_profile(..., profile_dir=...)
```

У `load_profile` параметр `profile_dir=None`: значение `None` означает, что используется обычная локальная папка. Если путь передан, выбирается именно он. Отсутствующий явно выбранный файл даёт ошибку, а не скрытый переход к другому резюме. Именованный аргумент `profile_dir=...` показывает назначение передаваемого пути на каждом шаге.

Это небольшая передача зависимости: функция получает расположение данных извне, вместо неявного выбора другой папки. В тесте можно указать учебные профили и сделать личную папку недоступной — так проверяется реальная независимость от личных данных.

## Подготовленный реальный прогон

```powershell
.\scripts\run_evaluation.ps1 -Manifest examples/fixtures/evaluation/cases.json -ProfileDirectory config/profile_examples
```

До девяти платных запросов, по одному на случай, с маскированным вводом ключа и без повторов. При ошибке прогон останавливается. Это анализ **вымышленных вакансий по вымышленным профилям**, а не оценка личных перспектив пользователя. Личный девятикейсовый корпус не менялся.

Можно выбрать один случай:

```powershell
.\scripts\run_evaluation.ps1 -Manifest examples/fixtures/evaluation/cases.json -ProfileDirectory config/profile_examples -CaseIds demo_other_profession
```

Ожидания хранятся отдельно от модельного входа и проверяются после ответа. Их не нужно менять только для получения зелёного отчёта: сначала читаем источник, ответ и причину расхождения. Формальная сборка и модульные тесты не доказывают, что Luna правильно классифицирует каждый новый пример. Это установит отдельный живой прогон и ручной разбор.
