# 27. Один проход Watcher

`examples.run_once` соединяет уже работающие сценарии. По умолчанию показывает план без сети; `--live` включает поиск и платный анализ. Необходимы переменные текущей PowerShell-сессии из `scripts/start_session.ps1`.

Один проход последовательно запускает поиск, загрузку карточек для двух основных профилей и анализ каждого профиля. `subprocess.run` запускает существующие модули через тот же Python. Список аргументов передаётся без командной оболочки. Если этап вернул ненулевой код, последующие этапы останавливаются; уже сохранённые данные остаются в базе и файлах.

Лимит по умолчанию: до 10 новых карточек и трёх платных анализов на профиль. Поиск показывает кандидатов, а не рекомендации. Защита от повторной оплаты и остановка на ошибках остаются в существующих модулях. Это ручной проход: расписание и Telegram будут следующими этапами.

## Как работает передача между программами

`run_step(name, arguments)` получает название этапа и список аргументов, например `['examples.collect_hh', '--live', ...]`. Вызов `subprocess.run([sys.executable, '-m', *arguments], cwd=ROOT)` запускает дочерний Python из того же виртуального окружения. Звёздочка перед `arguments` разворачивает список в отдельные элементы команды. `cwd` задаёт рабочую папку; `check=False` позволяет самостоятельно обработать код завершения.

Дочерний процесс наследует переменные текущего окна PowerShell. Поэтому токены не нужно вставлять в командную строку: каждый модуль читает нужную переменную из окружения. При ненулевом `returncode` функция возвращает `False`, а основной сценарий прекращает следующие этапы.

Чтобы загрузка и анализ получили именно результаты текущего поиска, главный сценарий заранее создаёт уникальный путь и передаёт его через `--run-directory`. Поисковый модуль записывает туда `candidates.json`. Следующие этапы получают путь к этому файлу, а полные карточки и история попыток сохраняются в SQLite. Это две разные передачи: путь к выдаче передаётся аргументом, карточки и история читаются из базы.

После одного запуска можно увидеть одновременно завершённые и незавершённые этапы. Неисправный анализ сохраняется отдельно, а его API-попытка остаётся зарегистрированной: перезапуск не должен незаметно оплатить её снова. Отдельные локальные проверки сохранённых ответов не являются повторным ответом модели.

В реальном проходе модель сослалась на `work_formats` при оценке возможности работы из России, хотя это поле описывает только формат. Одновременно она указала точную строку «Удаленная работа из любого города России». Валидатор контракта 4 теперь убирает не относящуюся к стране ссылку только при явно подтверждающей строке и фиксирует исправление; по одному `REMOTE` страну устанавливать нельзя.
