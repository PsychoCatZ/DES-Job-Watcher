# 26. Текстовое подтверждение и смешанные форматы HH

Карточка может содержать `ON_SITE`, `REMOTE`, `HYBRID` одновременно и отдельно обещать в описании «Удаленный формат работы». Смешанный список сам по себе не подтверждает полную удалёнку. Но отдельная явная текстовая формулировка является самостоятельным основанием.

В первой проверке контракта 4 модель вернула и ID такого фрагмента, и ссылку на смешанное поле. Старый валидатор проверял поле как самостоятельное подтверждение и отвергал весь ответ. Цитаты по ID при этом разрешились корректно.

Ревизия проверки 2 для контракта 4 удаляет избыточную ссылку на смешанное поле только при выбранном фрагменте с узко распознаваемой положительной формулировкой удалённой работы. Изменение записывается в `semantic_corrections`; исходный JSON модели сохраняется. Отрицания, гибрид с обязательным офисом и одно смешанное поле таким способом не принимаются. Это не универсальная интерпретация условий и не изменение исторического валидатора контракта 3.

Программное представление хранит `validation_revision: 2`. Уже полученный ответ можно перепроверить локально: отдельный файл содержит первоначальную ошибку, отпечатки исходного входа и ответа, отпечаток модуля валидатора и новую проверенную оценку. Первоначальный статус API-попытки не переписывается и не даёт права на повторную оплату.

Тесты проверяют совместное текстовое и структурное доказательство, неизменность оригинального ответа, отрицания и офисные ограничения, а также прежний случай с единственным `REMOTE` без текстовой цитаты. Платного запроса для такого исправления не требуется.
