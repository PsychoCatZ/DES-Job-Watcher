# DES Job Watcher

Python-проект персонального поиска работы на HH с анализом относительно отдельных резюме. Основной упор — два направления с рабочим опытом:

- письменная и техническая поддержка;
- разметка данных и оценка качества ИИ.

Разработка, AI-интеграции и автоматизация — дополнительное направление, которое включается явно. Уроки сопровождают разработку и не требуют отдельного прохождения перед следующим рабочим шагом.

Проект развивается небольшими работающими шагами вместе с уроками. Автор определяет требования, проверяет решения и изучает Python; AI-агент помогает проектировать, писать и проверять код. Это текущий прототип, а не готовый фоновый сервис.

## Что уже работает

- Учебный поиск на вымышленных данных; отдельные сетевые примеры HH с явным включением.
- Подготовка входа из одного профиля и полного описания вакансии.
- Версионированные правила, инструкции и JSON-контракт ответа.
- Один анализ через OpenAI Responses и последовательный прогон корпуса без автоматических повторов.
- Проверка структуры ответа, существования цитат и ссылок на опыт.
- Отдельные решения о соответствии и маршруте показа: `show`, `review`, `exclude`.
- Локальный пересчёт правил по сохранённым ответам, отчёты и модульные тесты.

SQLite-история карточек и версий, сохранение оценок и локальные Markdown-отчёты реализованы. Постоянный сбор, Telegram, состояние просмотра и развёртывание сервиса пока не реализованы. Регистрация приложения HH одобрена. Официальный API-клиент и запуск `python -m examples.collect_hh --live` подготовлены: поддержка и AI-data по умолчанию, первая страница каждого запроса, дедупликация ID внутри запуска и локальный отчёт. Это кандидаты из поиска, ещё без оценки полных описаний. Первый токен можно получить через `--issue-token`; ввод скрыт, значения остаются в памяти. Подробности — в уроке 17. HTML-пример остаётся экспериментом.

## Правила оценки

Задачи вакансии сопоставляются с фактами выбранного резюме. Опыт разработки с AI-инструментами учитывается как практический опыт; он не заменяет отсутствующую предметную квалификацию. Зарплата, график и занятость — информация для пользователя, без снижения оценки.

Явно обязательный голос или видеовстречи без полноценной письменной альтернативы — препятствие. Неизвестный канал общения нейтрален. Неизвестный навык не означает, что кандидат им не владеет. Профессиональные сомнения не должны скрывать вакансию от пользователя.

Это персональная конфигурация правил, а не универсальная модель отбора кандидатов. Точность смысловых выводов модели не гарантируется проверкой JSON или цитат.

## Быстрый запуск без ключей и сети

Python 3.12, команды из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe examples\search_hh.py
.\.venv\Scripts\python.exe -m examples.validate_analysis --demo
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

Сетевой доступ нужен для первоначальной установки HTTPX. Приведённые примеры и тесты сами API не вызывают.

Для работы с вымышленными профилями:

```powershell
.\.venv\Scripts\python.exe -m examples.setup_demo_profiles
.\.venv\Scripts\python.exe -m examples.run_evaluation --manifest examples/fixtures/evaluation/cases.json --profile-directory config/profile_examples --synthetic
```

Первая команда создаёт три **вымышленных** профиля в игнорируемой папке `config/profiles`. Она откажется заменять существующие файлы. Вторая явно использует учебные профили из `config/profile_examples` и синтетический режим, только проверяет сборку девяти вымышленных вакансий, без обращения к модели. Для второй команды предварительное копирование профилей не требуется. Учебные профили не описывают реального человека и не должны использоваться для персональных рекомендаций. Обычный режим откажется отправлять явно помеченный синтетический профиль; флаг не может включиться из текста вакансии.

Для реальной работы нужны собственные профили с источниками и отдельный локальный корпус. Публичные шаблоны не заменяют извлечение и проверку своего резюме. Личные данные и результаты отсутствуют в репозитории.

## Ключи и реальные запросы

Ключ OpenAI передаётся через временную переменную окружения. `scripts/run_openai.ps1 -InputPath <путь-к-входу>` запрашивает ключ с маскировкой и выполняет один платный вызов. `scripts/run_evaluation.ps1` предназначен для локального личного корпуса и делает до одного запроса на случай. До ввода ключа выполняется проверка сборки.

`--live` явно включает сеть; не используйте его для обычных тестов. При ошибке повторов нет. Таймаут не доказывает, что сервер не обработал запрос. Ключи, токены, реальные резюме и журналы в Git не добавляются. Внешнему LLM передаётся выбранный текст профиля и вакансии: состав данных нужно проверять до реального запуска.

## Структура

| Путь | Назначение |
| --- | --- |
| `des_job_watcher/` | Проверка ответов, сборка запроса, API-адаптер и исполнитель корпуса |
| `examples/` | Небольшие запускаемые сценарии |
| `config/profile_examples/` | Только вымышленные учебные профили |
| `config/profiles/` | Личные профили, локально, исключены из Git |
| `config/contracts/`, `config/rules/`, `prompts/` | История схем, правил и инструкций |
| `tests/` | Проверки на вымышленных данных |
| `docs/lessons/` | Открытые версии уроков |
| `data/` | Локальные входы и результаты, исключены из Git |

Текущие версии: правила 3, инструкция 5, контракт 3, политика оценки 3. Синтетические профили версии 2; режим фиксируется отдельно в метаданных запроса и отчёте.
